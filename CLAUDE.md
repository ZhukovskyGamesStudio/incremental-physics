# Правила для агентов

## Дизайн-документ — всегда

Перед любой работой над игрой прочитай дизайн-документ (он подгружается ниже целиком):

@DESIGN.md

- Каждое решение по фичам, балансу, наградам, ценам, прогрессии, UI и текстам сверяй со столпами из
  раздела 2 и тремя проверочными вопросами. Если запрос или существующий код им противоречит — скажи
  об этом геймдизайнеру до того, как делать, а не закрывай задачу локальным решением.
- Не считай текущий код правильным замыслом: пункты «[как сейчас]» можно ставить под сомнение.
- Когда геймдизайнер принимает решение — обнови DESIGN.md: нужный раздел и строку в журнале решений
  (раздел 11). В пункты «[утверждено]» пиши только то, что он явно сказал.
- Нашёл противоречие со столпами — добавь его в «Открытые вопросы» (раздел 10).
- Субагентам, которые принимают дизайн-решения, передавай ссылку на DESIGN.md и требование сверяться с ним.

## Проект

- Unity, C#, код в `Assets/Scripts`. Данные игры (буквы, формулы, приборы, перки, дерево) — `Assets/Scripts/Core/Defs.cs`,
  правила — `Assets/Scripts/Core/GameState.cs`.
- Тексты для игрока — на русском. Термины — по словарю из DESIGN.md (раздел 9).
- Файлы с кодом — в CRLF; `sed -i` в Git Bash ломает окончания строк, правь через Edit или Python.
